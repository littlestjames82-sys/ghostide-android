# Building GhostIDE Android from a clean checkout

Hardening plan item 7 (Oct 2026). The build is a manual recipe
(aapt2 + javac + d8 + zipalign + apksigner, no Gradle) driven by
`build.sh`. Every input lives under one workspace root, `$WS`
(default `~/workspace`, override with `GHOSTIDE_WS`). This file is
the complete input list; if it is not listed here, the build does
not need it.

## Toolchain (pinned, not in git)

| Input | Version | Source |
| --- | --- | --- |
| JDK | 17 (workspace `jdk17/`) | any JDK 17 distribution |
| Android SDK platform | android-36 (API 36) | `platform-36_r02.zip` from dl.google.com/android/repository, SHA-1 2c1a80dd4d9f7d0e6dd336ec603d9b5c55a6f576 |
| Android build-tools | 36.0.0 | `build-tools_r36_linux.zip`, SHA-1 b0b6376977657e8ad9b969bacf4093601da2c6fb |
| Node + npm | current LTS | only to build the frontend bundle in the ghost-ide repo (`npm run build` -> `web/app.js`) |

Layout expected by `build.sh`: `$WS/android-sdk/build-tools/36.0.0`,
`$WS/android-sdk/platforms/android-36/android.jar`, `$WS/jdk17`.

## Source inputs (in git)

| Tree | Repo | Notes |
| --- | --- | --- |
| `ghost-ide/` | littlestjames82-sys/ghost-ide | frontend (`web/`), `server.py`, `refdocs.json`, `tools/` (incl. the eco bundle gate). Build `web/app.js` first with `npm run build`. |
| `ghostide-apk-build/` | littlestjames82-sys/ghostide-android | app sources, `build.sh`, this file, `python-runtime/` (its `stage/` outputs are produced by `python-runtime/assemble.py` then `assemble_git.py`, in that order). |
| 25 eco tool trees | one repo per tool under littlestjames82-sys | the eco.zip step reads `<tool>/src` for the 24 bundled tools + GhostSlice from `$WS/<tool>/`; the exact set is `BUNDLED + LIBRARY` in `ghost-ide/tools/eco_bundle_gate.py`, and the built zip carries `eco-manifest.json` with versions and test counts. |

## Binary inputs (NOT in git)

| Input | Where | Provenance |
| --- | --- | --- |
| llama.cpp JNI libs | `$WS/ghostbot/phone/native/libs/arm64-v8a/*.so` | prebuilt from the MrGhosty on-device build |
| Python runtime stage | `ghostide-apk-build/python-runtime/stage/` | generated by the assemble scripts above from `python-runtime/` sources and debs |
| Signing keystore | `$WS/ghostide-apk/debug.keystore` | generated by build.sh if absent. An existing keystore is required for update compatibility: a fresh one produces an APK that will not install over earlier builds. The separate production upload key (store path) lives outside the repos and is never used by `build.sh`. |

`assemble_inputs.sh` copies both repos and all binary inputs into a
clean root, excludes build outputs (the staged `www/`, `eco.zip`,
`pyhome.zip`, `git-templates.zip`, `refdocs.json` are regenerated by
`build.sh`), symlinks the toolchain, and writes `INPUTS.sha256`
over the binary inputs so two builders can confirm they started
from identical material.

## Build and verify

```sh
bash assemble_inputs.sh /path/to/cleanroot
GHOSTIDE_WS=/path/to/cleanroot bash /path/to/cleanroot/ghostide-apk-build/build.sh
```

Expected: `BUILD-OK`, APK at `<cleanroot>/ghostide-apk/ghostide.apk`.
Verification used for the reproducibility claim (v2.11.0): per-entry
SHA-256 of every file inside the APK except `META-INF/*` (the
signature block) is identical between the maintainer build and the
clean-root build. Zip container timestamps may differ; entry
contents do not.

## Known limits

- arm64-v8a only (matches the native libs).
- The eco bundle reflects the sibling tool checkouts at build time;
  `eco-manifest.json` inside the APK records what went in.
- The model files are never in the APK; the app downloads them on
  device with size + SHA-256 gates.

## Continuous integration

`.github/workflows/ci.yml` on ghostide-android runs four jobs on
every push to main: **frontend** (checks out ghost-ide, builds the
bundle, runs the harness suite and the DOM-stub boot gate),
**jvm-tests** (tests/jvm/run.sh: BkTest, ZgTest, PcTest),
**java-compile** (aapt2 + javac against API 36), and **probes**
(the four live-server suites from ghost-ide/tools/probes). The
probes job uploads its logs as an artifact when it fails. CI
compiles but does not assemble the APK: the binary inputs above
are not in git, so assembly stays the local build.sh path
described here.
